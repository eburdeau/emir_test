Architecture — modèle 3 tables

Le message DATREC suit une hiérarchie Document → Rpt[] → TxDtls[] → RcncltnRpt[]. Le schéma Hive est organisé en trois tables correspondant aux trois niveaux d'agrégation naturels.

Document └── DerivsTradRcncltnSttstclRpt └── RcncltnSttstcs (choice: DataSetActn | Rpt[]) │ ├── DataSetActn → ligne dans datrec_rpt (dataset_actn = 'NOTX') │ └── Rpt[] maxOccurs=unbounded ── TABLE datrec_rpt ├── RefDt ├── RcncltnCtgrs ├── TtlNbOfTxs └── TxDtls[] maxOccurs=500 000 ├── CtrPtyId ├── TtlNbOfTxs └── RcncltnRpt[] maxOccurs=unbounded ── TABLE datrec_rcncltn_rpt ├── TxId (UTI) └── MtchgCrit ├── CtrPtyMtchgCrit ├── ValtnMtchgCrit ├── CtrctMtchgCrit └── TxMtchgCrit (dont éléments ARRAY[]) BizData / AppHdr (head.001.001.01, facultatif) ── TABLE datrec_msg_header
Principe de dénormalisation. La table principale datrec_rcncltn_rpt répète sur chaque ligne les champs du Rpt parent (RefDt, catégories) et du TxDtls parent (identifiants contrepartie), évitant ainsi les jointures à chaud pour les analyses courantes. Les champs à cardinalité unbounded sont stockés en ARRAY<STRUCT<…>> et exploitables via LATERAL VIEW EXPLODE.

Table 1 · datrec_msg_header

facultative

Stocke l'en-tête Business Application Header (head.001.001.01) quand le fichier XML est livré dans une enveloppe BizData. Alimentée 1 fois par fichier source. Joignable sur biz_msg_idr.

Partition : ingestion_dt DATE (date de chargement, pas de date métier — le BAH ne porte pas de date de référence propre). 
CREATE TABLE IF NOT EXISTS datrec_msg_header (
  biz_msg_idr   STRING     -- AppHdr/BizMsgIdr — identifiant message (max 35)
 ,msg_def_idr   STRING     -- AppHdr/MsgDefIdr — doit valoir "auth.091.001.02"
 ,cre_dt        TIMESTAMP  -- AppHdr/CreDt — horodatage UTC (format Z imposé)
 ,fr_lei        STRING     -- AppHdr/Fr/OrgId/Id/OrgId/Othr/Id — LEI émetteur (TR)
 ,to_lei        STRING     -- AppHdr/To/OrgId/Id/OrgId/Othr/Id — LEI destinataire
 ,src_file_nm   STRING     -- Nom du fichier XML source
 ,ingestion_ts  TIMESTAMP  -- Horodatage du chargement (UTC)
)
COMMENT 'En-tête BAH (head.001.001.01) — 1 ligne par message'
STORED AS PARQUET
TBLPROPERTIES ('parquet.compress' = 'SNAPPY')
PARTITIONED BY (ingestion_dt DATE);

Colonnes ARRAY unbounded

maxOccurs="unbounded" dans TxMtchgCrit
Pattern co-indexé. Plusieurs groupes d'éléments unbounded dans TxMtchgCrit sont co-indexés dans le XSD (dates effectives, dates fin, montants). Ils sont regroupés ici en un seul ARRAY<STRUCT<…>> par groupe logique plutôt qu'en tableaux parallèles, évitant les désynchronisations à la lecture. Utilisez LATERAL VIEW INLINE() pour les dénormaliser à la requête.

Exemples de requêtes

Transactions non réconciliées sur le montant notionnel (Val1 ≠ Val2)
SELECT
    ref_dt
   ,rptg_ctr_pty_lei
   ,othr_ctr_pty_lgl_lei
   ,unq_tx_idr
   ,ntnl_amt_frst_leg_val1_amt  AS ntnl_val1
   ,ntnl_amt_frst_leg_val2_amt  AS ntnl_val2
   ,ABS(ntnl_amt_frst_leg_val1_amt - ntnl_amt_frst_leg_val2_amt) AS ecart
FROM  datrec_rcncltn_rpt
WHERE ref_dt = '2024-03-01'
  AND  ntnl_amt_frst_leg_val1_amt != ntnl_amt_frst_leg_val2_amt
ORDER BY ecart DESC;
Dénormalisation des OthrPmt (LATERAL VIEW INLINE)
SELECT
    r.unq_tx_idr
   ,p.tp_val1, p.tp_val2
   ,p.dt_val1, p.dt_val2
   ,p.amt_val1, p.amt_ccy_val1

Comptage des non-réconciliations par classe de commodité
SELECT
    cmmdty_val1_cat            AS commodity_cat
   ,cmmdty_val1_sub_cat        AS commodity_sub
   ,COUNT(*)                   AS nb_nrec
FROM  datrec_rcncltn_rpt
WHERE ref_dt BETWEEN '2024-01-01' AND '2024-03-31'
  AND  cmmdty_val1_base_pdct IS NOT NULL
  AND  (cmmdty_val1_base_pdct != cmmdty_val2_base_pdct
        OR cmmdty_val1_sub_pdct != cmmdty_val2_sub_pdct
        OR cmmdty_val1_addtl_sub_pdct != cmmdty_val2_addtl_sub_pdct)
GROUP BY 1, 2
ORDER BY nb_nrec DESC;

Choix de conception

  • Dénormalisation totale du grain RcncltnRpt. Les champs RefDt et identifiants contrepartie sont répétés sur chaque ligne plutôt que normalisés, ce qui évite les jointures dans les requêtes analytiques courantes tout en restant cohérent avec la logique du parseur Python existant.
  • ARRAY<STRUCT<…>> pour les éléments co-indexés. Les triplets (dates effectives, dates fin, valeurs) des échéanciers sont regroupés dans un seul tableau de structs. Cela garantit l'intégrité de la co-indexation et simplifie les requêtes LATERAL VIEW INLINE.
  • Commodity aplatie en 5 colonnes scalaires. Les 14 sous-types de AssetClassCommodity6Choice (Agrcltrl, Nrgy, Envttl, etc.) et leurs propres sous-types sont mappés sur cmmdty_*_cat / cmmdty_*_sub_cat / BasePdct / SubPdct / AddtlSubPdct. Cette approche normalise les 14 hiérarchies en une structure plate cohérente.
  • Partition sur ref_dt DATE. La date de référence est la dimension temporelle naturelle pour les analyses réglementaires (réconciliation à date J). Elle pilote le pruning de partitions dans la quasi-totalité des requêtes EMIR.
  • Précisions décimales du XSD. DECIMAL(25,5) pour les montants (types ActiveOrHistoricCurrencyAnd20Amount), DECIMAL(24,19) pour les quantités et deltas (19 décimales prescrites), DECIMAL(11,10) pour les taux et pourcentages.
  • datrec_msg_header facultative. Le BAH n'est pas présent dans tous les fichiers DATREC. La jointure sur biz_msg_idr est optionnelle ; NULL dans la table principale signale un fichier livré sans enveloppe.
